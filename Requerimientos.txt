1. Requerimientos Funcionales (RF)
a)Gestión de Autenticación y Seguridad

RF-01 (Control de Acceso): El sistema debe permitir el inicio de sesión seguro de usuarios mediante la validación de credenciales (Username y Password).
RF-02 (Niveles de Acceso):** El sistema debe restringir el acceso a los módulos internos basándose en el nivel asignado (al menos 3 niveles o roles de usuario distintos).
RF-03 (Manejo de Sesiones):** El sistema debe implementar un control de sesiones activas para proteger las páginas internas de accesos no autorizados y permitir un cierre de sesión seguro.

### Módulo de Administración de Usuarios

* **RF-04 (CRUD de Usuarios):** El sistema debe permitir registrar, editar, visualizar y controlar el estado (activar/desactivar) de los usuarios dentro de la plataforma.
* **RF-05 (Asignación de Roles):** El sistema debe permitir asociar un rol o nivel de acceso específico a cada usuario creado.

### Módulo de Categorías e Inventario

* **RF-06 (CRUD de Categorías):** El sistema debe permitir registrar, editar, eliminar y visualizar las categorías de los productos.
* **RF-07 (CRUD de Productos):** El sistema debe permitir registrar, editar, eliminar, consultar disponibilidad y realizar búsquedas exhaustivas de productos.
* **RF-08 (Almacenamiento Mínimo del Producto):** Cada producto debe guardar obligatoriamente los siguientes campos: código, nombre, categoría, precio, stock y estado.

### Módulo de Gestión de Clientes

* **RF-09 (CRUD de Clientes):** El sistema debe permitir el registro, modificación, eliminación y búsqueda de los datos de los clientes.
* **RF-10 (Datos del Cliente):** Cada registro de cliente debe almacenar de manera obligatoria: nombre completo, teléfono, correo electrónico y dirección geográfica.

### Módulo de Control de Ventas y Facturación

* **RF-11 (Transacciones Múltives):** El sistema debe permitir registrar ventas agregando múltiples productos dentro de una misma transacción.
* **RF-12 (Cálculo Automático):** El sistema debe calcular de forma automatizada el Subtotal, el IVA y el Total de la venta en base a los productos seleccionados y sus respectivas cantidades.
* **RF-13 (Comprobantes de Venta):** El sistema debe generar un comprobante simple por cada venta realizada con éxito.
* **RF-14 (Historial de Ventas):** El sistema debe proveer una interfaz para visualizar el registro histórico de las ventas efectuadas.

### Reglas de Negocio (Integridad del Inventario)

* **RF-15 (Validación de Stock):** El sistema debe impedir la venta de productos que no cuenten con existencias disponibles en el inventario.
* **RF-16 (Actualización de Existencias):** El sistema debe actualizar automáticamente el stock en la base de datos al momento de registrar una nueva venta o al proceder con la anulación de una venta existente.

### Módulo de Reportes Administrativos

* **RF-17 (Reportes Estratégicos):** El sistema debe generar reportes específicos para la toma de decisiones gerenciales, incluyendo de forma obligatoria:
* Listado de productos con bajo stock para alertas de reabastecimiento.
* Historial de ventas realizadas filtradas por rango de fechas.
* Monto total acumulado de lo vendido en el periodo seleccionado.
* Listado de los productos más vendidos.

## 2. Requerimientos No Funcionales y Técnicos (RNF)

### Arquitectura Tecnológica

* **RNF-01 (Backend y Lógica):** El sistema debe estar desarrollado utilizando PHP como lenguaje de programación principal del lado del servidor.
* **RNF-02 (Base de Datos):** El motor de base de datos relacional para la persistencia y almacenamiento de la información debe ser MySQL.
* **RNF-03 (Frontend e Interfaz):** La interfaz de usuario debe construirse utilizando los estándares web esenciales del lado del cliente: HTML, CSS y JavaScript.

### Diseño y Usabilidad

* **RNF-04 (Diseño Responsive):** La interfaz gráfica del sistema debe ser adaptativa para garantizar una visualización y operatividad correcta en diferentes dispositivos (computadoras de escritorio, portátiles, tablets y smartphones) y resoluciones de pantalla.
* **RNF-05 (Validación de Formularios):** Todos los formularios de captura de datos deben implementar validaciones estrictas en el frontend y backend para garantizar la integridad y el tipo de dato correcto antes de procesarse en el servidor.

### Estructura de Software

* **RNF-06 (Programación Modular):** El código fuente debe estar organizado bajo un enfoque arquitectónico modular, separando estrictamente la lógica de negocio, la presentación (interfaz de usuario) y la capa de acceso a datos mediante una estructura limpia de carpetas y archivos independientes.

## 3. Matriz de Entregables del Proyecto

Para fines de control de calidad y evaluación del proyecto, se establecen los siguientes elementos obligatorios para la entrega:

* **Código Fuente:** Repositorio estructurado y funcional con la arquitectura modular implementada.
* **Persistencia:** Script SQL con la estructura de tablas, relaciones y restricciones de la base de datos.
* **Documentación Técnica:** Capturas de pantalla del sistema en funcionamiento y un manual básico de usuario y de administración del sistema.
* **Control de Versiones:** Repositorio formal alojado en las plataformas GitHub o GitLab.
* **Evaluación:** Defensa presencial del proyecto, demostrando el cumplimiento de las reglas de negocio estipuladas.
